# Licensing guide

This is a plain-language project guide, not legal advice and not a replacement
for the license texts.

The repository already permits commercial use while keeping covered work open:

- specification prose and documentation use
  [CC BY-SA 4.0](../LICENSE), which permits sharing and adaptation, including
  commercially, with attribution and share-alike obligations; and
- schemas, examples, fixtures, workflows, and software use
  [MPL 2.0](../LICENSE-CODE), which permits commercial and proprietary larger
  works while requiring modifications to MPL-covered source files to remain
  available under MPL 2.0.

An additional MIT license is not necessary to permit commercial implementation.
MIT is permissive but would not require improvements to the covered standard or
code to remain open. The existing split better matches the stated objective:
commercial products can implement and ship the standard, while modifications to
the shared specification and covered source files remain available under their
respective terms.

Commercial adopters should review the complete license texts and retain required
notices. Implementing the public format does not make an application's unrelated
code or proprietary live-storage design part of this repository or automatically
subject it to either license.

The same applies when the portable model is used inside a knowledge-management
service or exposed through an application-specific API: obligations follow the
covered specification and code artifacts, not the architectural role in which an
adopter uses them. Adopters remain responsible for their own legal review.
