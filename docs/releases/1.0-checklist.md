# 1.0 promotion checklist

**Release candidate:** `1.0.0-rc.1`  
**Promotion:** `1.0.0`  
**Promotion date:** 2026-08-18  
**Disposition:** approved

This is the authoritative checklist for promoting the 1.0 release candidate to
a stable release. Other release documents provide evidence, but do not replace
this checklist. A release manager MUST NOT promote a candidate until every row
is checked and contains all three of the following:

1. a link to reviewable evidence;
2. an identified approver (a person or the linked governance approval record);
3. an ISO 8601 approval date.

An unchecked row is blocking. It MUST NOT be treated as waived or
not-applicable unless the row links to a public decision that gives the reason,
scope, approver, and date. Such a decision permits the row to be marked checked
as an approved non-applicability decision; a blank field, private discussion,
or release-manager assertion is not a waiver. Any change to the candidate after
an approval invalidates every affected row and requires it to be unchecked and
approved again.

For this promotion, **v1.0 release governance approval (non-author
maintainer)** means the approval of the exact release set recorded in the
[1.0 release evidence](../release-evidence-1.0.md#governance-approval). It is the
required non-author-maintainer approval under [governance](../../GOVERNANCE.md),
and no additional release approvers were designated.
